# デザインの決まり

このサイトの見た目と画面構成の決まりです。GX Career のデザイン原則(`gx-career/designs/DESIGN-PRINCIPLES.md` と `SITE-PLAN.md`)のうち、このサイトに当てはまるものを選び、読み手と目的に合わせて直しました(2026-10-22)。

各項目に状態を付けています。**現行** は今のサイトがすでに守っている決まり、**未対応** は決まりとして採用したがまだ直していない箇所です。変更するときは各項目の「確認」で確かめます。決まりとページの都合がぶつかるときは、黙って破らずにユーザーに相談します。

---

## 1. このサイトは何のためにあるか

山林所有者が、自分の山について**判断できる状態になる**ための場所です。物を売るサイトではありません。読み手には高齢の方が多く、相続や管理は急いで決めることではありません。

そのため、このサイトでは**行動を急がせるより、分かることを増やす**ほうを優先します。相談は「読んだ結果、必要だと思った人が迷わず申し込める」状態にしておけば十分です。

## 2. ページの 3 つの役割

ページごとに、装飾をどこまで使ってよいかが変わります。

| 役割 | ページ | 使ってよいもの |
| --- | --- | --- |
| 伝える | トップ、各対象者の入口(さとやま不動産、企業・個人の方、私たちについて) | 写真、写真の上の文字、飾りのブロック 1 つまで |
| 読む | 森林を知る、ガイド、お悩みから探す、持続可能な森林経営 | 図版。飾りは使わない |
| 道具 | 森林オープンデータ | 地図と表。飾りも写真も使わない |

- 確認: 新しいページを作るとき、まずどの役割かを決めてから組む。

## 3. 最初の画面で伝えること

ページを開いてスクロールせずに見える範囲で、知らない人が次の 3 つに答えられるようにします。

1. **だれ向けか**(例: 山林をお持ちの方へ)
2. **何のページか**(例: さとやま不動産 — 山林・里山の管理と出口整理)
3. **読むと何が分かるか、何が得られるか**(気分ではなく中身。例: 初回のインタビューは無料)

見出しは気持ちに訴える一文でよいですが、そのすぐ下に仕組みを一文で書きます。

- 状態: さとやま不動産のページは満たしている(現行)。トップは「山林をお持ちの方」という言葉と「初回無料」が最初の画面にない(未対応)。
- 確認: 最初の画面より下を手で隠し、知らない人が 3 つに答えられるか。

## 4. 行動の示し方

**目立つボタンは 1 画面に 1 つ**にします。目的は売り込みではなく、迷わせないことです。英国政府のデザインシステム(GOV.UK)も、主なボタンを 1 ページに複数置かないよう定めています。理由は「主な行動が 2 つ以上あると、それぞれの効果が弱まり、次に何をすればいいか分かりにくくなる」ためです。

- **塗りのボタン**はその画面の主な行動 1 つだけ。2 つ目は枠線のボタンか文字リンクにする。
- **トップのヒーロー**は「さとやま不動産について」(読む)を塗り、「無料相談を申し込む」を枠線にする。読んでから申し込む順番が、このサイトの読み手に合っている。(未対応: 今は CSS の順番のせいで 2 つとも同じ塗りに見える。`styles.css` の `.button-outline` が後ろの `.button` に上書きされている)
- **ヘッダーの「無料相談」**は全ページで同じ枠線の形にする。(未対応: トップだけ下線の文字リンクになっている)
- **相談への入口**は、ヘッダー、フッター、本文の区切り(ページの終わりなど)に置く。本文のすべての区切りに置かない。
- **売り込みの手法は使わない**: 画面に貼りつく追従ボタン、期限や残り数で急がせる表現、ポップアップ、閉じにくい案内。
- **ボタンの動き**: マウスを乗せたら色が変わるだけにし、浮き上がり・影・移動は付けない。(未対応: 外部リンクのボタンは銅色に変わり、影が付き、1px 動く。`styles.css:32-44`)
- 文言の決まりは `AGENTS.md`(「無料相談を申し込む」/「お問い合わせをする」)に従う。
- 確認: 1 画面ずつ、塗りのボタンが 1 つ以下か。

## 5. 誠実さ

- 実績・事例は、実際にできてから載せる。想定のケースも載せない(現行)。
- 売却価格や認証の結果を約束しない(現行、`AGENTS.md`)。
- 無料の範囲と、費用がかかる前に必ず見積もることをはっきり書く(現行、`.flow-fees`)。
- 提供状況は言葉で書く(提供中 / 準備中)。色だけで示さない(現行)。
- 写真は自社のものか使用許諾のあるものだけにし、許諾の条件でクレジットが必要なら、ページに書く。(未対応: 各写真の出どころを記録していない)
- 確認: ページ上のすべての数字と主張が、本番で本当に正しいか。

## 6. 色

**ひとつの色には意味をひとつだけ**持たせます。

- 基本は紙色の地、墨色の文字、深い緑。強い色はこの 3 つ以外に増やさない。
- 銅色(`#b9915b` / `#c8894c`)は今、外部リンクのボタンにマウスを乗せたとき、トップでキーボード操作中のリンクの枠、トップの「願い」カードの上の線、費用と提供状況のバッジの枠、お悩みページの番号に使われていて、意味が 1 つに決まっていない。役割を 1 つに絞る。キーボード操作中の枠は全ページ共通の 1 色にする。(未対応)
- 色は `styles.css` の `:root` に名前を付けて定義し、そこから使う。今は名前付きが 5 色しかなく、CSS 全体では 269 色の値が直接書かれている。紙色に近いほぼ同じ色が多い。(未対応。見た目を変えない整理なので、CSS 整理第 1 段階と同じく前後のピクセル差 0 で確かめる)
- 文字と背景のコントラスト比は 4.5 以上(現行、`AGENTS.md`)。
- 確認: 新しい色を足すとき、その色が何を意味するかを一言で言えるか。

## 7. 文字

- 書体は Noto Sans JP の 1 種類(現行)。
- 本文は 20px 前後、行間はたっぷり取る(現行)。高齢の読み手が多いので、GX Career の小さめの数値(本文 14px など)は使わない。
- 文字の大きさは決まった段階の中から選ぶ。今は CSS に 64 通りの指定がある。(未対応。段階の表を作り、`:root` に置く)
- 本文の 1 行は 35〜40 字までにする。(未対応: トップのリード文は 1440px 幅で約 51 字)
- 見出しは `word-break: auto-phrase` で文節改行する(現行、`AGENTS.md`)。
- Web フォントは CSS の `@import` ではなく、各ページの `<head>` の `<link>` で読み込む。`@import` だとスタイルシートを読み終わるまでフォントの読み込みが始まらない。(未対応)

## 8. 面・線・影・アイコン

- 角は四角(角丸なし)。丸は点と円形のしるしだけ(現行)。
- 影はメニューや確認画面など、手前に重なるものだけ(パスワード画面を含む)。(現行、ただし §4 のボタンの影は例外として直す)
- グラデーションは、写真の上の白い文字を読みやすくする目的だけ(現行)。
- 飾りのブロック(トップの「山を読む / 山の次を描く」の傾いたカードなど)は 1 ページに 1 つまで(現行)。
- アイコンは見分けるために必要なところだけ。見出しや入力欄の中には置かない(現行)。

## 9. 写真

- WebP・1 枚 300KB 目安、英小文字のケバブケースのファイル名、`alt` 必須(現行、`AGENTS.md`)。
- 対象者の違うページには、違う写真を使う。今はトップ、私たちについて、サービス一覧、さとやま不動産、企業・個人の方の 5 ページが同じ棚田の写真(`nature-capital-concept.webp`)で始まり、「だれ向けか」が写真から伝わらない。(未対応)

## 10. 動き

- 動きはほとんど使わない(現行)。画面が動くと読みにくくなる読み手がいる。
- `prefers-reduced-motion`(動きを減らす設定)を尊重する(現行)。
- スクロールを横取りする演出(GX Career のスクロールショーなど)は使わない。

## 11. 変更したときの確認

1. `docker compose up -d` で http://localhost:8000/ を開き、デスクトップ幅とスマホ幅(720px 以下)の両方で見る(`AGENTS.md`)。
2. 文字のコントラスト比 4.5 以上。
3. リンク切れがないこと(今は手作業。スクリプト化は未対応)。
4. 見た目を変えない整理は、前後の全ページ撮影でピクセル差 0。

## 12. GX Career から採らなかったもの

理由とともに残します。同じ議論を繰り返さないためです。

- **「黄色は読み手自身のもの」の決まり**: 読み手の個人データ(診断結果など)を表示しないサイトなので、その色が指すものがない。
- **青鉛筆の手描きイラスト・ハッチング**: GX Career のブランドそのもの。このサイトの見た目は Figma の紙・墨・緑と実景の写真。
- **スクロールの演出と時間の決まり**: 演出がないので不要。高齢の読み手には使いにくくなる。
- **4 分野の色分け**: このサイトの対象者はナビの言葉で分かれており、色より確実。
- **小さく詰めた文字と高い密度**: 業務ツール向けの数値。読み手が違う。
- **部品キット・Tailwind・データベース前提の確認**: ビルドのある Web アプリ向け。このサイトは静的 HTML で、共通部品は `styles.css` のクラス(`.flow-fees` など)で作る。
- **画面に貼りつく相談ボタン**: GX Career ではスマホに置く案があるが、このサイトでは §4 の理由で使わない。
