## 3. 公開前の確認(シナリオ)

ガイド 6 章にもとづく。ローカルで確認 → 公開 → 公開 URL で確認、を分けて記録する。

| シナリオ | 確認すること |
|---|---|
| チラシ A の QR から入り、相談ボタンを押す | フォームの最後の質問に `flyer-a / …` が入っている |
| 印なしで入り、別のページから相談ボタンを押す | `web / 押したページ` が入っている |

| 共有(LINE・メールに URL を貼る) | 新ドメインの共有画像とタイトルが出る |
| パスワード画面 | どのページでも出ない |
| 旧 URL(github.io)を開く | 新ドメインへ転送される |

## 4. セキュリティの確認(09)

- サイト側は静的ファイルのみで、個人情報を保存・送信しない(相談内容は Google フォームのみ)
- 流入元の印(`?src=`)に個人情報を入れない。印は英小文字・数字・ハイフンのみ受け付ける
- パスワード画面はクライアント側だけの仕組みで、保護にはなっていない。公開前に、見られて困る情報がサイトに無いことを確認する(未公開のページ・内部メモ・`archive/` は `docs/` の外にある)
- フォームの回答シートの共有範囲(閲覧できる人)を確認する → 専用メールのメンバーと同じ人に個別に共有、「リンクを知っている全員」にしない【決定:2026-10-29】
