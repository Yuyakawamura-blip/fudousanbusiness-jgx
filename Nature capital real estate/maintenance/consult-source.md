# 相談の流入元の記録(DESIGN.md 11 計測 / 05 価値検証)

チラシ・SNS・看板・紹介のどれから来た相談かを、Google フォームの回答に自動で残す仕組み。

## 仕組み

- 全ページが `docs/consult-source.js` を読み込む
- URL に `?src=flyer-a` のような印があると、そのタブを閉じるまで覚えておく(sessionStorage。個人情報は含めない)
- ページ内の Google フォームへのリンクに、事前入力として `印 / 押したページ` を付ける
  - 例: `flyer-a / services/satoyama-real-estate/`
  - 印が無い人は `web / concerns/` のようになる
- 印に使える文字は英小文字・数字・ハイフン(40 字まで)。それ以外は無視して `web` 扱い

## 有効にする手順(1 回だけ)

1. Google フォームに **記述式(短文)** の質問を 1 つ追加する
   - 質問: 「(自動入力)このフォームを開いたページ」
   - 説明: 「入力不要です」/ 必須にしない / フォームの一番最後に置く
2. 「︙」→「事前入力したリンクを取得」→ 追加した質問に `test` と入れて「リンクを取得」
3. リンクの中の `entry.数字=test` の `entry.数字` を、`docs/consult-source.js` の `FORM_ENTRY` に入れる
4. 「回答」タブ →「︙」→「新しい回答についてのメール通知を受け取る」を有効にする(3 営業日以内に連絡するため)
5. サイトから相談ボタンを押し、フォームの最後の質問に自動で値が入っていることを確認する

フォームの URL そのものは変わらない(リンクの末尾に事前入力が付くだけ)。

## 印の一覧

| 印 | 使う場所 | QR / リンク先(`<公開URL>` は独自ドメインが決まったら置き換える) |
|---|---|---|
| `flyer-a` | チラシ A「相続する予定の山、今のうちに整理しませんか」 | `<公開URL>/services/satoyama-real-estate/?src=flyer-a#inheritance` |
| `flyer-b` | チラシ B「手入れできない山、放置する前にご相談ください」 | `<公開URL>/services/satoyama-real-estate/?src=flyer-b#management` |
| `flyer-c` | チラシ C「森林・耕作放棄地・空き家…まとめて相談」 | `<公開URL>/concerns/?src=flyer-c#costs` |
| `sns-a` / `sns-b` / `sns-c` | SNS 広告の 3 案 | チラシと同じリンク先で印だけ変える |
| `sign-地域名(ローマ字)` | 看板(例: `sign-ebetsu`) | `<公開URL>/?src=sign-ebetsu` |
| `partner-名前(ローマ字)` | 森林組合・士業・金融機関に渡す紹介用 QR(例: `partner-xx-shinrin`) | `<公開URL>/?src=partner-xx-shinrin` |
| `web` | 印なし(検索・直接) | 自動 |

- 2 地域で配る場合は `flyer-a-sapporo` のように地域を足してよい(英小文字・数字・ハイフンのみ)
- 新しい印を作ったらこの表に足す

## 集計(回答シート)

回答シートの右に、次の列を手で足す。

| 列 | 入れるもの |
|---|---|
| 流入元 | `=INDEX(SPLIT(<自動入力の列>, " / "), 1)`(自動) |
| 連絡日 | 最初に連絡した日 |
| 有効相談 | 初回インタビューの日程が決まったら `1`(DESIGN.md の定義) |
| 除外理由 | 営業・いたずら・対象外(山林を含まない)など |
| 初回インタビュー日 | 日付 |

ピボットテーブル(行: 流入元、値: 回答数・有効相談の合計)で、流入元ごとに次を並べる。

- 送信数 → 有効相談数 → 面談化率(有効相談 ÷ 送信数)
- 相談獲得費 = その媒体にかかった費用(印刷・配布・広告費)÷ 有効相談数。費用は別の表に印ごとに記録する
- メールで来た相談は、初回の連絡で「何で知ったか」を聞き、同じ表に手で 1 行足す(流入元は `mail-` + 聞いた答え)

判定は計画書 7.3.2 のとおり、配布量・問い合わせ・有効相談・面談・案件化を一つの表で見て、継続・修正・停止を決める。件数が少ないうち(各案 5 件未満など)は差を結論にしない。

## 確認の記録

2026-10-28 ローカル(パスワード画面を外したコピー、テスト用 ID)で確認:

| 入力 | 期待 | 結果 |
|---|---|---|
| `services/satoyama-real-estate/?src=flyer-a` | `flyer-a / services/satoyama-real-estate/` | OK |
| 印なしで同ページ | `web / services/satoyama-real-estate/` | OK |
| `?src=<script>`(不正な値) | `web / top` | OK |
| `partners/?src=partner-...#x` | 印とページ、`#` は含めない | OK |
| `?src=flyer-b` で入ってから別ページへ移動 | `flyer-b / concerns/` | OK |
| 英語ページ | `web / forest/sustainable-forestry/en/` | OK |
| `FORM_ENTRY` が空 | リンクは変わらない | OK |
| `404.html` | 公開 URL でのみ確認可能(`<base href>` が公開パス固定のため) | 未確認 |

公開後にやること: 公開 URL で上の表をもう一度確認し、実際にフォームを 1 回送信して回答シートに値が入ることを見る。
